2. ChatGPT / OpenAI

2-1. ChatGPT WorkのData agent

新規 ★★★

事実： OpenAIは2026年9月10日、ChatGPT Work向けのData agentを発表しました。 企業データに接続し、変化の調査、回答、インタラクティブなダッシュボード作成、 共有などを行う機能として説明されています。 公式発表
分析： BIツールやデータ分析業務の一部を会話形式で代替する可能性があります。 一方、接続先データの定義誤り、期間・母集団の取り違え、 因果関係と相関関係の混同が、経営報告や監査資料に混入するリスクがあります。
監査・内部統制上の確認：
  • 接続可能なデータソースと、ユーザーごとの閲覧権限が一致しているか。
  • データ抽出・加工・分析・ダッシュボード共有の各操作が記録されるか。
  • 生成された指標について、元データ・計算式・更新時点を追跡できるか。
  • 経営会議資料、財務報告、顧客向け資料への利用に承認ルールがあるか。
  • 分析結果から外部システムを更新する場合、人的承認や二者確認があるか。

2-2. ChatGPT for Financial Services

新規 ★★★

事実： OpenAIは2026年9月10日、金融機関向けのChatGPT for Financial Servicesを発表しました。 金融データ、企業テンプレート、金融分析ワークフローを組み合わせ、 SAML SSO、SCIM、ロールベースアクセス制御、保持期間設定、 対応するワークスペースログの出力などを説明しています。 公式発表
分析： 金融機関における導入判断では、機能の有無だけでなく、 顧客情報、重要非公開情報、投資判断資料への利用範囲と、 出力の根拠・承認・保存を業務規程に落とし込めるかが重要です。
監査・内部統制上の確認：
  • 金融データ提供者との契約、利用目的、再利用・保存条件を確認。
  • 顧客情報、重要非公開情報、個人情報の入力制限を確認。
  • 回答中の引用・根拠情報が、利用者によって追跡可能か確認。
  • テンプレートや社内標準様式の変更管理・承認者を確認。
  • SSO、SCIM、RBAC、退職者・異動者のアカウント無効化を確認。

3. Gemini / Google

3-1. Windows向けGeminiアプリ

新規 ★★★

事実： Googleは2026年9月10日、Windows向けGeminiアプリを発表しました。 Alt + Spaceによる呼び出し、文書作成、タスク処理、画像・動画作成、 GmailやGoogle Drive等のGoogleアプリからの情報取得、 複数ステップのタスク処理を説明しています。 Windows 10および11向けにグローバル提供とされています。 公式発表
分析： 会社管理端末上で、許可なく個人アカウントや私用Googleサービスへ接続されると、 データ移転、シャドーAI、監査対象外の処理が発生する可能性があります。 Windows端末管理、ブラウザ管理、ID管理、DLPを一体で確認すべきです。
監査・内部統制上の確認：
  • 会社端末へのインストールを許可制またはソフトウェア配布管理下に置いているか。
  • 会社アカウントと個人Googleアカウントの利用を技術的に分離しているか。
  • Gmail、Drive、Calendar等の接続権限とOAuth同意を管理しているか。
  • Alt + Space等の常時呼び出し機能について、情報漏えい対策があるか。
  • 生成物の保存先、共有設定、外部送信、ログ取得範囲を確認しているか。

継続・拡張 ★★★

接続アプリ拡大に関する公式発表
分析： メール送信、予約、ファイル更新などの「外部作用」が発生する場合、 従来の生成AI利用規程だけでは不十分です。 操作前承認、権限の最小化、実行結果の確認、失敗時のロールバックを 業務プロセスに組み込む必要があります。
監査・内部統制上の確認：
  • エージェントが実行できる操作と、参照だけの操作を区分しているか。
  • メール送信、予約、購入、ファイル削除など高リスク操作に承認があるか。
  • 実行前の確認画面、実行後の結果表示、失敗・取消処理があるか。
  • 接続アプリの追加・変更が変更管理の対象になっているか。
  • ユーザーが連携を解除した場合、トークンや権限が確実に失効するか。

4. Claude / Anthropic

4-1. Enterprise Frontier Safeguards

新規・段階導入 ★★★

事実： Anthropicは2026年9月1日、Enterprise Frontier Safeguardsを発表しました。 顧客が管理するクラウドインフラにデータを保管しつつ、 不正利用の検知などの安全対策を組み合わせる仕組みとして説明されています。 段階的な提供で、開始は2026年秋以降とされています。 Claude Code、Claude Enterprise、Claude Platform、 Amazon Bedrock、Google Agent Platform、Microsoft Foundry等への対応が示されています。 公式発表
分析： セキュリティ対策を強化しながら、顧客環境内にデータを置く設計は、 金融、医療、公共、製造など規制業種で検討しやすくなる可能性があります。 一方、顧客側クラウドに保存されることで、アクセス権限、 保持期間、暗号鍵、ログ管理の責任分界が複雑になります。
監査・内部統制上の確認：
  • Anthropic、顧客、クラウド事業者の責任分界を契約で確認。
  • データ保存先、リージョン、暗号化、暗号鍵管理を確認。
  • ゼロデータ保持との関係、例外、対象モデル、移行時期を確認。
  • 不正利用検知の対象、誤検知時の救済、管理者通知を確認。
  • 検知・遮断・調査に関するログを監査証跡として取得できるか確認。

6. 内部監査への示唆

6-1. AIガバナンス

  • AI利用の責任者、リスクオーナー、承認者を明確化する。
  • 生成AI、検索拡張、業務エージェント、自動実行をリスク分類する。
  • 高リスク用途について、事前審査、利用目的、禁止事項、停止条件を定める。
  • モデル・機能・接続先の変更を、AI台帳に反映する。

6-2. IT全般統制・変更管理

  • 新モデル、モデル更新、機能追加、コネクタ追加を変更管理の対象とする。
  • 本番導入前に、精度、セキュリティ、権限、データ保護、業務影響を評価する。
  • モデルの自動切替や段階展開について、通知・承認・ロールバック手順を確認する。
  • 変更後に回帰テストを実施し、重要業務の出力品質を比較する。

6-3. アクセス管理

  • SSO、MFA、SCIM、RBAC、特権管理が適切に設定されているか。
  • 退職・異動・委託終了時に、AIサービスおよび接続アプリの権限が失効するか。
  • エージェントの権限が利用者本人の権限を超えていないか。
  • 管理者、開発者、一般利用者、監査担当者の職務分掌を確認する。

6-4. ログ管理・監査証跡

  • 利用者、日時、モデル、プロンプト、出力、参照データ、ツール実行を記録できるか。
  • ログの改ざん防止、保存期間、検索性、エクスポート可否を確認する。
  • 個人情報・機密情報を含むログへのアクセスを制限する。
  • 業務判断に利用したAI出力を、後日再現・検証できる状態にする。

6-5. 情報セキュリティ・AI利用ルール

  • 入力禁止情報、条件付き入力情報、入力可能情報を分類する。
  • 個人アカウント、未承認SaaS、私用端末へのデータ移転を制限する。
  • プロンプトインジェクション、データポイズニング、情報漏えいを想定する。
  • 外部サービス連携、OAuth同意、APIキー、シークレットを定期点検する。

6-6. AI出力の品質管理

  • 重要業務では、AI出力をそのまま確定情報として扱わない。
  • 根拠資料、引用、計算式、参照時点、データ更新日を確認する。
  • 財務、法務、医療、人事、与信、投資判断などでは人による承認を必須化する。
  • 誤回答率、修正率、拒否率、重大インシデントを継続的に測定する。

6-7. 業務へのAI導入

  • 導入効果だけでなく、業務分掌、承認、証跡、例外処理への影響を評価する。
  • AIが作成した成果物と人が承認した成果物を区別できるようにする。
  • 自動実行を認める業務と、人手確認を必須とする業務を明確にする。
  • 障害時に従来業務へ戻れる代替手順を整備する。

7. 今後ウォッチすべき事項

  1. エージェントの実行権限： メール送信、ファイル更新、予約、購買、コード実行等に対する承認・停止・取消機能。
  2. データ接続の拡大： Google Workspace、Microsoft 365、CRM、ERP、データウェアハウスへの接続範囲と監査ログ。
  3. モデル自動更新・廃止： 既存モデルからの自動切替、提供終了日、API互換性、再テスト要否。
  4. 企業向けデータ保持： 学習利用の有無、保持期間、バックアップ、削除証明、地域別保管。
  5. 監査証跡の標準化： プロンプト、モデル、参照データ、出力、ツール実行、承認履歴を一体で取得できるか。
  6. 専門領域モデル： 金融、医療、サイバー、生物学等での用途制限、検証済み組織要件、独立評価。
  7. 料金・無料プランの変更： 今回の確認範囲では、対象サービス全体の一律変更を確認できず。 各社の公式料金ページ、管理者向け通知、契約更新通知を継続確認する。
  8. 将来日付の発表： 2026年9月13日・14日付の入力項目は、2026年9月12日時点では未到来のため、 次回レポートで実績・公式掲載状況を再確認する。
