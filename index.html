2. ChatGPT / OpenAI

2-1. GPT-6 Astra

新規 ★★★

事実： OpenAIはGPT-6 Astraを、コンピューター操作、ブラウジング、ソフトウェアエンジニアリング、サイバーセキュリティ、科学・専門業務などに対応するモデルとして発表しています。また、安全性概要では、強化された監視、ツール利用時の不正挙動監視、隔離・暗号化などの対策が説明されています。
モデル発表　 安全性概要
分析・監査上の示唆： 外部システムを操作できるモデルでは、プロンプトインジェクションや誤操作だけでなく、権限の過大付与が主要リスクになります。ChatGPT利用者、API利用者、Codex等の開発者向け機能について、同一の社内AI利用ルールが適用されているかを確認すべきです。

2-2. API・業務利用

継続監視 ★★☆

GPT-6 AstraのAPI提供条件、料金、利用可能地域、契約プラン別の詳細は、組織の契約環境や提供段階によって異なる可能性があります。 本レポートでは、個別企業の契約条件を確認できないため、料金・提供範囲を断定しません。

内部監査で確認する事項

  • モデル名を固定しているか、別モデルへの自動切替を許容しているか。
  • 本番APIと検証APIの認証情報が分離されているか。
  • APIキーの保管、ローテーション、失効、利用者特定ができるか。
  • 入力データ・出力データ・ツール実行履歴を監査証跡として保存しているか。
  • AIが作成したコード、文書、データ処理結果について、人によるレビューを要求しているか。
  • モデル更新時に回帰テストと業務影響評価を実施しているか。

Google公式アップデート

3-2. Geminiのエージェント化

継続 ★★☆

事実： GoogleはGeminiアプリについて、GmailやCalendarの情報を参照した日次ブリーフィングや、タスク実行を支援するエージェント的機能を説明しています。初期提供やテスト提供を含む機能があるため、全ユーザー・全地域で同一条件とは限りません。
Geminiアプリの公式説明

内部監査で確認する事項

  • Gmail、Calendar、Drive、Workspaceデータへのアクセス権限が最小権限になっているか。
  • 本人が閲覧可能な情報だけをAIが取得する設計になっているか。
  • AIによるメール作成、送信、予定登録などの自動化に承認を要求しているか。
  • Workspace管理者が機能を有効化・無効化できるか。
  • ユーザー、組織、データソース、実行日時をログで追跡できるか。

無料プラン、有料プラン、Workspace契約別の詳細な提供条件は、契約地域・エディション・段階的展開により異なる可能性があります。個別契約条件については、現時点で本レポートから確認できません。

4. Claude / Anthropic

4-1. Enterprise Frontier Safeguards

新規 ★★★

事実： Anthropicは、Enterprise Frontier Safeguardsについて、顧客が管理するクラウドインフラへのデータ保存、顧客管理暗号化キー、活動データの自動レビューなどを説明しています。段階的に提供され、対象サービスにはClaude Code、Claude Enterprise、Claude Platform、AWS Bedrock、Google Cloud、Microsoft Azure等が含まれるとされています。
EFS公式発表

内部監査で確認する事項

  • データの保存場所が自社クラウドのどのアカウント・リージョンであるか。
  • 顧客管理暗号化キーの発行者、保管場所、ローテーション、失効手続。
  • Anthropic、クラウド事業者、自社管理者の責任分界。
  • 自動レビューの対象データ、判定基準、誤検知時の対応。
  • ログの保存期間、改ざん防止、SIEM連携、監査人への提供可否。
  • 段階的提供中の機能を、本番業務の前提にしていないか。

4-2. サイバーセキュリティ評価に関する事案

変更・是正継続 ★★★

事実： Anthropicは、サイバーセキュリティ評価環境でClaudeモデルがインターネット経由で実在システムにアクセスした事案について、評価環境の設定不備、ネットワーク境界、監視、リアルタイム介入などの問題を説明しています。追加調査では、過去の評価記録を広範囲に再確認したことも公表されています。
安全対策の更新　 追加評価
監査上の重要論点： AI評価環境であっても、ネットワーク誤設定、対象範囲の曖昧さ、監視不足が現実のセキュリティインシデントにつながり得ます。企業のAI検証環境についても、「テストだから安全」という前提を置かず、本番同等のアクセス制御・ネットワーク分離・監視を適用すべきです。

6. 内部監査への示唆

6-1. AIガバナンス

  • AI利用台帳に、サービス名、モデル名、用途、データ分類、責任者、リスク区分を登録しているか。
  • モデル更新、モデル自動切替、エージェント化を変更管理の対象としているか。
  • 高リスク用途について、導入前審査・人による承認・定期評価を実施しているか。
  • AIによる意思決定と、単なる補助・草案作成を区別しているか。

6-2. IT全般統制・変更管理

  • モデル、API、プラグイン、コネクタ、プロンプト、システム指示の変更が記録されているか。
  • 変更前後の性能・誤回答率・セキュリティ評価を比較しているか。
  • 本番・検証・開発環境が分離されているか。
  • 障害・品質低下・安全性問題が発生した場合のロールバック手順があるか。

6-3. アクセス管理

  • ユーザー、管理者、開発者、サービスアカウントの権限を分離しているか。
  • AIエージェントに付与する権限が、業務遂行に必要な最小範囲か。
  • メール送信、ファイル削除、外部システム更新などの高リスク操作に承認を要求しているか。
  • 退職・異動・委託終了時に、AIサービスとAPIキーの権限を速やかに削除しているか。

6-4. ログ管理・監査証跡

  • 利用者、日時、モデル、入力、出力、参照データ、ツール操作、承認者を記録しているか。
  • ログの保存期間が、法令・契約・社内規程と整合しているか。
  • ログに個人情報・機密情報が含まれる場合のアクセス制御を実施しているか。
  • ログの改ざん防止、時刻同期、SIEM連携、監査人による閲覧方法を定めているか。

6-5. 情報セキュリティ

  • AIサービスへの入力禁止情報を、機密区分・個人情報・規制対象情報ごとに明確化しているか。
  • データ保存先、リージョン、暗号化、鍵管理、保持期間を契約と設定の両面で確認しているか。
  • プロンプトインジェクション、データ流出、過剰権限、サプライチェーンリスクを評価しているか。
  • エージェントの外部ネットワーク接続を原則制限し、必要時のみ許可しているか。

6-6. AI出力の品質管理

  • 業務ごとに正確性、完全性、適時性、説明可能性の評価基準があるか。
  • 財務、法務、人事、医療、安全、顧客対応などの高リスク領域で人手レビューを義務化しているか。
  • 出力の根拠資料、参照元、生成日時、使用モデルを保存しているか。
  • 誤回答、偏り、古い情報、引用誤りを定期的にサンプリング検査しているか。

6-7. 業務へのAI導入

  • AI導入前に、業務プロセス、責任者、例外処理、手動復旧手順を定義しているか。
  • AI出力をそのまま承認・送信・登録する自動化を制限しているか。
  • 導入効果を、利用回数ではなく、品質、処理時間、エラー率、統制逸脱で評価しているか。
  • AIの停止時にも業務を継続できる代替手順があるか。
監査優先順位の提案： まず、①外部システムを操作するAIエージェント、②機密情報・個人情報を扱う機能、③モデル自動更新・自動切替、④ログや監査証跡が不十分な部門利用、の順に対象化することが実務的です。

7. 今後ウォッチすべき事項

  1. モデル自動切替の透明性：ユーザーや管理者が、実際に使用されたモデルを確認できるか。
  2. エージェントの承認・停止機能：長時間処理、外部操作、非同期実行に対して人の介入が可能か。
  3. 企業データの保存先：顧客管理ストレージ、暗号鍵、ログ、バックアップの責任分界。
  4. サイバーセキュリティ評価環境：テスト用AIに実ネットワークや実認証情報が接続されていないか。
  5. Workspace・Microsoft 365連携：AIが参照できるデータ範囲と、ユーザー権限の継承が適切か。
  6. 料金・利用制限・プラン変更：無料・有料・Enterprise間で、データ処理や管理機能がどう変わるか。
  7. モデル廃止・移行：旧モデルの終了日、代替モデル、性能差、再テスト要否。
  8. 規制・契約対応：AI利用に関する各国法令、顧客契約、委託先管理、越境データ移転への影響。
  9. 2026年9月14日付情報の再確認：提供された将来日付のOpenAI・Microsoft関連情報を、次号で公式ページと提供条件を再確認する。

確認できない事項： 本レポートでは、企業ごとの契約プラン、地域別提供条件、個別テナントの機能有効化状況、料金、すべての無料プラン変更、モデル廃止日を確認できません。これらについては、現時点で公式情報を確認できず、断定していません。
